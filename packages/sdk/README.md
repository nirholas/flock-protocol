# @flock/sdk

Client for the Flock index engine: derive addresses, build every instruction, decode the index
account, quote issuance and redemption, price a bid, and pull the market data a methodology screens
on.

```bash
pnpm add @flock/sdk @solana/web3.js
```

## Read an index

```ts
import { Connection, PublicKey } from "@solana/web3.js";
import { FlockClient, fetchPricesE9 } from "@flock/sdk";

const client = new FlockClient(new Connection(rpcUrl), new PublicKey(process.env.FLOCK_PROGRAM_ID!));
const snapshot = await client.snapshot(new PublicKey(indexMint));
const prices = await fetchPricesE9(snapshot.account.components.map((c) => c.mint.toBase58()));

console.log(snapshot.account.symbol);
console.log("NAV per token", Number(client.navPerToken(snapshot, prices)) / 1e9);
console.log("weights", client.weights(snapshot, prices).weights.map((bps) => bps / 100));
```

## Quote and issue

```ts
const amount = 5n * 10n ** 9n;                       // 5 whole index tokens
const { required } = client.quoteIssue(snapshot, amount);   // per component, in its own base units
const instruction = client.issueInstruction({ snapshot, user, amount, slippageBps: 50 });
```

The quote applies the pending streaming fee first, exactly as the program does, so it holds even for
a fund nobody has touched in months.

## Exports

- `FlockClient` - snapshots, quotes, weights, NAV, auction view, issue and redeem instructions
- `instructions` - every instruction, byte-identical to the on-chain builders
- `decodeIndex` - the account decoder
- math: `unitsIn`, `unitsOut`, `unitsFromBalance`, `streamingFeeTokens`, `premiumAt`, `bidCost`,
  `weightsBps`, `unitsForWeights`
- prices: `fetchPrices`, `fetchPricesE9`, `fetchTokenStats` (Jupiter public API, no key)
- `explainError` - turns `custom program error: 0x14` into the sentence behind it

## Tests

```bash
pnpm test              # parity, layout, math, price parsing
FLOCK_LIVE=1 pnpm test # also hits the live Jupiter endpoints
```

`test/parity.test.ts` compares every instruction this package builds against an artifact generated by
the Rust builders, so the two cannot drift. `test/layout.test.ts` decodes an account the program
itself laid out, so a field added on the Rust side without updating the decoder fails here.
